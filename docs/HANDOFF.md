## 3. My plan: the API a client can call (all under `/api/plan`, JSON, `{ success, message, data }`)
Reliability update: `GET /history` lists owned finished/replaced and expired plans as summaries `{ plans: [{ id, title, goalType, startDate, deadline, createdAt, readOnly: true }] }`. `GET /history/:id` returns `{ plan, readOnly: true }` as a snapshot without later sheet overlays. Unowned, invalid or unfinished IDs give 404. Both routes require login. Expired-plan item mutations give 409. `DELETE /history` clears finished and expired history. Reviews require a due, unskipped item and allow one submission per study day, with protection across calendar changes. Concurrent stale replies give 409 or 422, depending on when the saved result is read.

The history browser is read-only. After early completion, the Plan tab offers an optional revision round with explicit preview and start. Pull tomorrow is also in the Plan tab. Today keeps its one Start button.

Problem-note autosave now orders per-problem requests and keeps account-specific pending edits/deletions in browser storage until acknowledged. Reload/remount/reconnect recovery is tested; no claim of cross-tab/device write conflict resolution. Notes publishing now requires a replica set (including Atlas), validates before writes and replaces in a transaction; standalone databases are refused safely and failures set a nonzero exit code. Never run it against the live database as an agent.
Public: `POST /preview` body = the form (below). Login (cookie session, same as the rest of the app): `GET /` , `POST /`, `DELETE /`, `DELETE /history`, `POST /changes/preview`, `POST /changes/apply`, `GET /review?weekStart=YYYY-MM-DD`, `POST /items`, `PATCH /items/:id`, `DELETE /items/:id`, `PATCH /items/:id/star`, `POST /items/:id/result`, `POST /items/:id/review`, `POST /items/:id/skip`, `POST /items/:id/unskip`.
- **The form** (`validators/plan.validators.js`): `goalType` placements | role | bigtech; `style` one-topic | mixed; `weeks` 1 to 52; `weekdayHours` and `weekendHours` (0 or 0.5 to 12); `restDay` null or 0 (Monday) to 6 (Sunday); `startDate` optional (defaults to the current study day; from yesterday to 60 days ahead); `sheetSlug` (placements and bigtech; bigtech allows only `neetcode-150` or `striver-sde`); `roadmapSlug` (role); `subjects` from os, dbms, cn, oops, hld; `knownTopics` topic ids; `pace` faster | standard | slower. `POST /` also takes `title`, `targetRole`, `replace`.
- **Preview answer:** `{ startDate, deadline, finishDate, earlyDays, pace, notices[], coverage { syllabusMinutes, plannedMinutes, extraMinutes, leftOutCount, leftOutMinutes, alreadySolved, byGroup }, week1 { week, from, to, minutes, items[] } }`. It includes only the first calendar week with tasks and reports `nothing-fits` when there is content but no task can be scheduled.
- **`GET /`** gives `{ plan, today, finished }`. `plan` has the settings, `coverage` (with `leftOut[]`), `notices` and `items[]` (`id`, `key`, `type`, `ref`, `link`, `title`, `plannedMinutes`, `day`, `part`, `core`, `starred`, `locked`, `skipped`, `result`, `doneAt`, `nextReviewDay`, `solvedOnSheet`, ...). `today` is `{ date, isToday, items[], minutes, startItem, onTrack { status, daysBehind, missedItems, suggestRebuild, text } }`: **the Today screen shows only this** (carried-over items first, then today's, then due reviews; a review item has `originalKey` and its original item's `id` is the one to send to `/review`). Treat `solvedOnSheet: true` as done.
- **Changes:** `POST /changes/preview` supports rebuild, hours, lighter and pace changes. Rebuild can take a new deadline. The preview returns the finish date, time and coverage totals, and a diff with a checksum. Always show the diff before applying. `/changes/apply` takes the same body plus the checksum and gives 409 when the preview has gone stale.
- **Ticking:** `PATCH /items/:id { done: true, result? }` or `POST /items/:id/result { result: alone | hints | solution }` (a notes section sends `{ quizScore: 0..5 }`); the three buttons "Solved alone", "With hints", "Needed the solution" call `/result`. A DSA tick also marks the problem solved on its sheet. `PATCH /items/:id { day }` moves (at most 3 days, locks). `DELETE` only removes items the student added; an item from the plan is skipped instead.
- **Limits** (`server/src/shared/config/limits.js`): preview 20 a minute per IP; 10 saved plans an hour; 20 changes a minute; 60 ticks a minute; 600 items per plan.
