# Roadmap source notes: DevOps & Cloud (11 Nov 2026)

Facts are restated in our own words. Tags: [V] read verbatim, [S] from the fetch tool's summary of an unread part. Time ranges, goals, checkpoints and projects are our estimates and opinions. Written for a non-technical reader (owner rule). Status: read by us; one AI reviewer (not an outside reader).

## Pages used and what we took
- **Pro Git (git-scm.com/book/en/v2)** (CC BY-NC-SA 3.0): ten chapters (getting started, basics, branching, Git on the server, distributed Git, GitHub, tools, customizing, other systems, internals). "What is Git?" [V]: snapshots not differences; nearly every operation is local; integrity by checksums; data is generally only added; three states modified, staged, committed. **GitHub docs "What is GitHub?"** [V]: repositories hosted in the cloud; GitHub across the software lifecycle.
- **Linux Journey** (moved to labex.io/linuxjourney, "no cost and no sign-up" per its page): groups: command line, text processing, user management, permissions, processes, packages; devices, filesystem, boot, kernel, logging; networking (basics, subnetting, routing, DNS). **man7.org man pages**: HTML man pages from the Linux man-pages project. TLDP "Introduction to Linux" was read (2008, old) and not linked. The GNU Bash manual returned HTTP 429 twice and was not read.
- **AWS "What is Amazon VPC?"** [V]: VPCs, subnets, IP addressing, routing, gateways and endpoints, peering, flow logs, VPN; a default VPC per Region; no charge for the VPC itself, some components and public IPv4 addresses are charged. **IAM** [V]: identities, authentication and authorization; IAM itself no extra charge. **S3** [V]: buckets, objects, keys, versioning, bucket policies; pay for use, a free tier for new customers. **EC2** [V]: instances, AMIs, instance types, EBS volumes, key pairs, security groups; Free Tier plus on-demand, savings plans, reserved, spot, per-second billing. The AWS pages "what is DevOps" and "what is CI/CD" are 404 and were not used; the Well-Architected page was read only in its introduction.
- **Docker docs** [V]: overview (platform, images, containers, daemon, client, registries, Linux namespaces); `docker run` (general form, options, foreground/background -d, networking, volume and bind mounts, exit codes 125, 126, 127, CPU/memory/block I/O limits; the tail is [S]); Compose (multi-container apps from one YAML file); Build overview (Buildx client, BuildKit server).
- **GitHub Actions docs** [V]: CI/CD platform; workflows (YAML in `.github/workflows`), events, jobs, actions, runners; quickstart creates a first workflow and shows results in the Actions tab; the CI concept page is a 404, replaced by the "Building and testing your code" tutorial index (Go, Java, .NET, Node.js, Python, Ruby, Rust and others).
- **Kubernetes docs**: overview (why needed; what it is not: not an all-in-one PaaS, does not build code, ships no databases) and "Learn Kubernetes Basics" (create a cluster, deploy an app, explore, expose, scale, update); both pages read in part, rest [S]; CC BY 4.0 per summary. **Terraform intro** [V]: write, plan, apply; state; modules; works with any infrastructure.
- **Prometheus overview** [V]: open-source monitoring and alerting toolkit; multi-dimensional data model; PromQL; pull model over HTTP; service discovery (Apache 2.0). **Grafana "Get started"** [V]: first dashboard, data sources such as Prometheus. **Google SRE book table of contents** [V] (CC BY-NC-ND 4.0): monitoring is chapter 6, release engineering chapter 8; also chapters on alerting, on-call, troubleshooting, postmortem culture.
- **The Twelve-Factor App** [V]: I codebase, II dependencies, III config, IV backing services, V build, release, run, VI processes, VII port binding, VIII concurrency, IX disposability, X dev/prod parity, XI logs, XII admin processes (last updated 2017).

## Our own wording, not from a page
Step order; the plain-language glosses; the idea that "post-incident reviews" are blameless (the SRE book lists postmortem culture; the word "blameless" was not read on a page and is flagged as general knowledge); "the least access idea" (general security principle); the claim that CI/CD means building, testing and releasing automatically (the Actions page calls it a CI/CD platform; the longer wording is ours); every time range, checkpoint and project.
