## HTTP (RFC 9110, RFC 9113, RFC 9114, MDN)
- Safe methods: GET, HEAD, OPTIONS, TRACE (RFC 9110 9.2.1, verbatim). Idempotent: PUT, DELETE and the safe ones (9.2.2, verbatim). POST is neither. PATCH is not in RFC 9110 (it points to RFC 5789, not read). Clients must not automatically retry non-idempotent requests (9.2.2).
- Status classes: 1xx interim, 2xx success, 3xx more action needed, 4xx client error, 5xx server failure (RFC 9110 s15, verbatim). 200 OK, 201 created (Location), 204 success with no body (15.3, verbatim).
- 301, 302, 304, 307, 308, 400, 401, 403, 404, 500-504 meanings come from the summary only (15.4 to 15.6). The verbatim note in 15.4: 307 and 308 keep the method; 301 and 302 may change POST to GET. 13.2.2: GET/HEAD with a false If-None-Match gets 304. 11.6.2: after 401 the client usually sends Authorization. We use these meanings because they are standard and consistent with the verbatim parts; the claims table marks them "summary".
- 429 is not in RFC 9110 (RFC 6585, not read). General knowledge; marked in the claims table.
- HTTP/2 (RFC 9113): many streams on one TCP connection, frames interleaved, header compression (HPACK), 9-byte frame header. It does not fix TCP head-of-line blocking (s1, verbatim).
- HTTP/3 (RFC 9114): runs over QUIC, which runs over UDP; a lost packet in HTTP/2 stalls all streams because TCP cannot see streams; QUIC has per-stream reliability and includes TLS 1.3 (1.1, 1.2, verbatim). If UDP is blocked, clients fall back to TCP (3.1).
- MDN HTTP overview: HTTP is stateless; cookies add sessions; HTTP runs over TCP (or TLS over TCP).
- Cookies (MDN): Set-Cookie then Cookie header; Secure = HTTPS only; HttpOnly = JavaScript cannot read it; SameSite Strict/Lax/None (None needs Secure); missing SameSite is treated as Lax; Max-Age beats Expires.
- Caching (MDN): max-age sets freshness; no-cache = may store but must revalidate; no-store = do not store; ETag + If-None-Match returns 304 with no body when unchanged; Last-Modified + If-Modified-Since is the other check.
- TLS (MDN TLS page; RFC 8446): encryption, integrity, authentication; TLS 1.3 is current; 1.0 and 1.1 should not be used. Handshake agrees version, cipher suite and keys. In 1.3 everything after ServerHello is encrypted; a full handshake takes one round trip before the client's Finished (inferred by the agent from the figure; we say "one round trip" as "about one"). **RFC 8446 pages say "obsolete, see RFC 9846"**: we cite TLS 1.3 as RFC 8446, replaced by RFC 9846; RFC 9846 itself was not opened.
- WebSocket (RFC 6455): starts as an HTTP GET with Upgrade: websocket; server answers 101 Switching Protocols; ws:// uses port 80, wss:// port 443 (verbatim).

## DNS and email (RFC 1034, 1035, 5321, 6409, 1939, 9051, 2131, 959, 4253)
- DNS parts: name space (a tree), name servers, resolvers (RFC 1034 2.4, verbatim). Labels up to 63 bytes, names up to 255 (3.1). Zones = units of authoritative data (2.4). Recursive = the first server chases the answer for you; iterative = the server answers with a referral (2.3, verbatim). TTL = seconds a record may be cached; 0 = do not cache (3.6).
- Record type numbers: A=1, NS=2, CNAME=5, PTR=12, MX=15, TXT=16 (RFC 1035 3.2.2, verbatim). MX has a preference (lower wins) and a mail server name (3.3.9). CNAME marks an alias (3.6.2 of RFC 1034). UDP messages are 512 bytes or less (RFC 1035 2.3.4, verbatim). Port 53 over UDP and TCP, and the TC (truncated) bit are in the summary only.
- Step-by-step lookup (resolver, root, TLD, authoritative): **no readable page gave this** (Cloudflare pages return 403, MDN URL page 404). We describe it from RFC 1034 roles plus general knowledge and mark the claim "general knowledge" in the claims table.
- SMTP: transport of mail between servers, relay on port 25; mail submission from users uses port 587 and requires authentication by default (RFC 6409 abstract, 3.1, 4.3, verbatim). MX records identify the next hop (RFC 5321 1.1). Port 25 is stated in RFC 6409's abstract.
- POP3: client retrieves mail held on the server, usually downloads then deletes; TCP port 110; IMAP is described as more advanced (RFC 1939 s1, s3, verbatim). IMAP: server keeps folders, client works on them, can resynchronise; ports 143 (cleartext) and 993 (implicit TLS) (RFC 9051 abstract, 2.1, verbatim).
- DHCP (RFC 2131): DISCOVER (broadcast), OFFER, REQUEST, ACK (verbatim); leases are for a limited time and can be extended; a relay agent passes messages across subnets (giaddr). Ports 67/68 are not in the text the agent read; the IANA table (batch A) lists bootps 67 and bootpc 68, which is our source for them.
- FTP: separate control and data connections (RFC 959 2.2, 2.3, verbatim); data port is control port minus one by default (3.2), so 20 and 21 follow if control is 21 (IANA lists 21, batch A). SSH: secure remote login, normally port 22 (RFC 4253 abstract, 4.1, verbatim).

## Routing and devices (RFC 2453, 2328, 4271; Wikipedia)
- RIP: distance-vector, metric is hop count, max 15, 16 = unreachable, update every 30 seconds, route times out after 180 seconds (RFC 2453 3.2, 3.4.1, verbatim). Port (UDP 520) not verified.
- OSPF: link-state, inside one autonomous system, every router holds the same database and builds a shortest-path tree rooted at itself, areas hide detail, routers flood link-state advertisements (RFC 2328 abstract, 1.1, verbatim). Dijkstra and protocol 89 not verified; we say "shortest-path tree" only.
- BGP: between autonomous systems, exchanges reachability including the list of ASes crossed, runs over TCP port 179 (RFC 4271 abstract, 1, 3, verbatim). "Path vector" word not read; we say "AS path".
- Hub: layer 1, repeats every bit to all other ports, one shared collision domain, half duplex, obsolete (Wikipedia Ethernet hub, verbatim). Switch: layer 2, learns MAC address per port, forwards a frame only to the right port, each port its own collision domain, still one broadcast domain (Wikipedia Network switch). Bridge: joins segments, learns source MACs, floods unknown destinations (Wikipedia Network bridge). Router: layer 3, reads destination IP, uses its routing table, joins networks (Wikipedia Router). Layer-3 switch exists (Wikipedia Network switch).
- Firewall: rules on traffic, between trusted and untrusted; packet filter on IPs, protocol, ports; connection tracking remembers conversations; application-layer firewalls understand protocols (Wikipedia Firewall, verbatim parts).
- Forward proxy: sits on the client side and fetches for clients; reverse proxy: sits in front of servers, looks like a normal server to clients; uses: load balancing, caching, TLS termination, compression; risks: holds TLS keys, single point of failure (Wikipedia Proxy server, Reverse proxy, verbatim).
- Attacks: DoS = make a service unavailable, usually by flooding; DDoS = many sources (Wikipedia). SYN flood = many SYNs, handshake never finished, backlog fills; defences include SYN cookies (Wikipedia SYN flood, verbatim, cites RFC 4987). ARP spoofing = forged ARP replies mapping attacker's MAC to someone else's IP; works because ARP replies are accepted without proof (Wikipedia, verbatim). MITM = attacker relays and may alter traffic; TLS certificates help (Wikipedia).

## Gap-fill read on 11 Nov 2026 (replaces "general knowledge" for the items below)
Terms: Wikipedia CC BY-SA 4.0; MDN Creative Commons (version not named); IETF RFCs as above; nginx docs "(c) F5, Inc., all rights reserved" (we restate, no copying); AWS docs have no licence line (we restate). IANA footer terms not read.
- Load balancing (Wikipedia Load balancing (computing), verbatim): round robin sends requests in turn and can be weighted; least connections picks the server with the fewest active connections; hash assigns by a hash; "power of two choices". Health checks (balancer removes failed servers) and persistence/sticky sessions (same user to the same backend; no automatic failover; shared session store is an alternative) come from the fetch summary only. The page does not define layer 4 / layer 7.
- nginx docs: round robin is the default; least_conn; ip_hash keeps one client on one server unless it is down; weights (3:1:1 example); open-source health checking is passive (a failed response marks the server failed, max_fails, fail_timeout); active health checks are in the paid version.
- AWS Elastic Load Balancing docs: sends traffic only to healthy targets and stops for unhealthy ones; Application LB picks a target by listener rules (HTTP level) and defaults to round robin; Network LB picks a target per flow using a hash of protocol, addresses, ports and TCP sequence number and keeps one TCP connection on one target. The pages do not use "layer 4/7", so we say people call a TCP-level balancer "layer 4" and an HTTP-aware one "layer 7".
- CDN (Wikipedia Content delivery network, verbatim): geographically distributed proxy servers; edge nodes closest to users; origin server is the source; origin shield protects it; pull caching (on request) and push caching (preloaded); users are routed by DNS-based request routing, global server load balancing, anycast and others. MDN Glossary CDN: servers in many places hold copies, nearest serves; downsides: third-party dependency, attack surface.
- Anycast (Wikipedia, verbatim): one IP address shared by servers in several places; routers send to the nearest (often fewest BGP hops); CDNs use it for HTTP or DNS; failover when a route is withdrawn.
- DNS (Wikipedia Domain Name System; operation part is fetch summary only): resolution through recursive caching server, root, TLD, authoritative server; TTL from seconds to weeks, so changes spread slowly; UDP for ordinary queries, TCP for large replies and zone transfers (infobox verbatim: port 53 UDP and TCP; intro: original design UDP only).
- RFC 6585 s4: 429 = too many requests in a time window; may include Retry-After; MUST NOT be cached. RFC 5789 s2: PATCH applies a set of changes; neither safe nor idempotent by definition, can be made idempotent; use conditional requests (If-Match with ETag); server applies all changes atomically.
- MDN status pages (14 read): 301 permanent move, a POST may become GET; 302 temporary; 304 conditional request, use cached copy, no body; 307 temporary, method kept; 308 permanent, method kept; 400 client error, repeating unchanged fails; 401 no valid credentials, WWW-Authenticate; 403 understood but refused, re-authenticating does not help; 404 not found (does not say temporary or permanent); 429 rate limit, Retry-After; 500 unexpected server condition; 502 invalid response from upstream; 503 not ready, maintenance or overload, Retry-After; 504 no response from upstream in time.
- IANA registry (updated 2026-11-10, verbatim rows): https 443 tcp and udp (RFC 9110); domain 53 tcp and udp; bootps 67; bootpc 68; ftp-data 20; ftp 21.
- Wikipedia Traceroute (verbatim): probes with TTL 1, 2, 3...; each router that drops the packet at zero replies with ICMP Time Exceeded; the destination replies Echo Reply or Destination Unreachable depending on probe type.
- Wikipedia TCP congestion control (verbatim): initial cwnd 1, 2, 4 or 10 MSS; +1 MSS per ACK in slow start; switch to congestion avoidance at ssthresh, +1 MSS per RTT; on timeout ssthresh = max(half of unacknowledged data, 2 MSS) and cwnd = 1 MSS; Tahoe restarts slow start on any loss; Reno on 3 duplicate ACKs halves cwnd and does fast recovery.
- Wikipedia SYN cookies (verbatim): the server encodes its queue entry in the initial sequence number of the SYN+ACK instead of storing it, and decodes it from the final ACK.
